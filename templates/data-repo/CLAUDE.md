# データ用リポジトリのルール

このリポジトリは、投げ込み・整理アプリのデータ置き場です。
データはすべて `items.json` に入っています。アプリ本体は別の公開リポジトリにあり、スマホやPCのアプリが、このファイルを読み書きして同期しています。

## items.json の形

```json
{
  "schema_version": 1,
  "items": [
    {
      "id": "uuid",
      "text": "本文(1行目が見出し扱い)",
      "note": "長めのメモ(任意)",
      "list": "inbox",
      "tags": [],
      "status": "open",
      "due": null,
      "estimate_min": null,
      "spent_sec": 0,
      "timer_started_at": null,
      "done_at": null,
      "created_at": "2026-10-15T09:00:00+09:00",
      "updated_at": "2026-10-15T09:00:00+09:00",
      "deleted": false
    }
  ]
}
```

### list の値

`list` には、次の表の **値** の列の文字列を入れる(日本語名は入れない)。

| 値 | 画面での名前 | 種類 |
|---|---|---|
| `inbox` | インボックス | 未分類(投げ込んだ直後) |
| `today` | 今日やる | 実行 |
| `todo` | やること | 実行 |
| `work` | 仕事へ転記 | 実行(会社の手帳に書き写すもの) |
| `chores` | 家事 | 実行 |
| `shopping` | 通販で買う | 実行 |
| `someday` | いつかやりたい | 実行 |
| `cards` | 買いたいカード | ためておくリスト |
| `books` | 読みたい本 | ためておくリスト |
| `movies` | 見たい映画 | ためておくリスト |
| `recipes` | 作りたいご飯 | ためておくリスト |
| `places` | 行った店 | ためておくリスト |

### その他の項目

- `status`: `open`(未完了)/ `done`(完了)/ `archived`(しまったもの)
- `due`: 期限。`"YYYY-MM-DD"` 形式の日付、または `null`。アプリの「今週」は今週の日曜日(月曜はじまり)
- `estimate_min`: 見込み時間(分)。未登録は `null`
- `spent_sec`: 実際にかかった時間(秒)。アプリのタイマーが記録する。**変更しない**
- `timer_started_at`: 計測中の開始時刻、または `null`。アプリが使う。**変更しない**
- `done_at`: 完了にした時刻、または `null`。完了にするときは現在時刻を入れる
- 古い項目には `estimate_min` 以降の欄が無いことがある。その場合は `null` / `0` / `null` / `null` とみなす
- `tags`: 文字列の配列
- 時刻(`created_at` / `updated_at`)は、日本時間のタイムゾーン付き ISO 8601 形式(例: `2026-10-15T09:00:00+09:00`)

## 作業のルール

- `inbox` の項目を読み、内容から適切な `list` に振り分ける。判断できないものは `inbox` に残す
- 必要に応じて `tags` や `due` を付ける
- 振り分けるときは、内容から見込み時間を推測して `estimate_min` に入れる(5 / 15 / 30 / 60 分のいずれかを目安に。見当がつかなければ `null` のまま)
- 変更した項目は、必ず `updated_at` を現在時刻に更新する(アプリは `updated_at` が新しいほうを採用して同期するため、更新しないと変更が端末側の古い内容で上書きされることがある)
- 変更していない項目の `updated_at` は変えない
- 項目を削除しない。消したいものは `deleted: true`、しまいたいものは `status: "archived"` にする
- `id` と `created_at` は変えない
- 新しい項目を作るときは、`id` に新しい UUID を使い、上の形のすべての項目をそろえる
- 質問(「今週やることは?」など)には、データを読んで回答する。質問に答えるだけのときは、ファイルを書き換えない
- 「15分で何ができる?」のような質問には、`status` が `open` で `estimate_min` がその時間以内の項目を、期限の近いものを優先して提案する。`work`(仕事へ転記)は除く
- 「見込みと実績はどうだった?」のような質問には、`status` が `done` で `spent_sec` が 0 より大きい項目について、`estimate_min` と比べて答える
- 書き換えたあとは、ファイルが正しい JSON であることを確かめる(例: `python3 -m json.tool items.json > /dev/null`)
- 作業後は、変更内容を要約したコミットメッセージでコミットする(例: `インボックス5件を振り分け: 今日やる2件、読みたい本1件、…`)
